# MossA 2.0.0-rc.1

The first release candidate for MossA 2 combines the React interface with a
shared Rust fitting core. Desktop calculations run natively; browser calculations
run locally in WASM workers. This is a prerelease for evaluation before stable
2.0.0.

## Included

- Multiple spectra and model alternatives, portable projects, autosave and Undo/Redo.
- Folding/calibration, ordinary line profiles, thin and full-transmission fitting,
  source calibration, fixed/linked bounds, and multistart fitting.
- Seeded model comparisons with complete diagnostics; corrected disappearing-component
  behavior and floating-point ties; compact native comparison execution.
- SVG/PNG/EPS/PDF figures, PDF fit reports, and CSV exports.
- Fixed a native progress race that could display starting/intermediate parameters
  beside completed-fit uncertainties; saved fitted projects were unaffected.
- Refined workspace controls and an updated, searchable offline manual with
  measured-data tutorials and light/dark screenshots.

## Validation limits

- Regression tests cover independent profile expressions, synthetic recovery,
  derivatives, direct-convolution references, saved-project restoration, native/WASM
  parity, cancellation, and seeded comparisons. Selected measured spectra have
  independent optimizer and SYNCmoss comparisons. These establish the documented
  cases, not universal physical accuracy or global optimization.
- Broad comparisons with independently executed MATLAB models/results remain
  incomplete. MATLAB-expression fixtures are independently transcribed formulas,
  not MATLAB execution output.
- **xVBF distributions and Gaussian-mixture source extraction remain experimental
  pending suitable measured-reference validation.** Selected numerical/synthetic
  checks are available; measured transmission checks with a supplied source do
  not independently validate source extraction.
- Reported parameter/fraction std are local-Jacobian estimates conditional on the
  chosen model and fixed inputs. Calibration/source and nuclear-constant systematic
  uncertainties are not generally propagated; general uncertainty coverage is not
  established. Convergence does not certify a global or physically unique solution.
- **Windows and Linux packaged GUI qualification remains open.** Platform build and
  native-command checks do not establish installation, native dialogs, offline help,
  exports, autosave/relaunch, or upgrades on those systems. Recorded native GUI
  checks are macOS only. Windows installers are unsigned.
- The SMS tutorial retains an unresolved pressure-label discrepancy between the
  supplied filename and internal header; its worked fits do not resolve provenance.

## Downloads and compatibility

- Browser: `MossA_2.0.0-rc.1_web.zip` contains the exact candidate and its manual.
  Extract and serve the directory over HTTP, then open `/MossA/`; the archive
  includes instructions. This allows candidate testing without changing the live site.

- macOS: universal Apple Silicon/Intel DMG and app archive. The release pipeline
  requires Developer ID signing, accepted Apple notarization and stapling before
  collecting these assets.
- Windows x64: EXE or MSI, both with the WebView2 offline installer. The rc.1 MSI
  numeric label is `2.0.0.10001`; the application and EXE use `2.0.0-rc.1`.
  Windows Installer ignores the fourth field for version comparisons; installation
  and replacement of existing previews still require runtime testing.
- Linux x64: AppImage or DEB. DEB requires the declared GTK/WebKit dependencies;
  AppImage compatibility depends on the host distribution.
- `SHA256SUMS.txt` and `build-provenance.json` identify the complete installer set,
  exact source revision, clean build identities, and accepted Apple submissions.

Save portable `.mossa` backups before testing. New formats are rejected by older
clients when their features cannot be preserved. MATLAB `.map` import,
additional instrument-specific binary/XML importers, batch/sequential/global
fitting and automatic desktop updates are not provided.

The draft candidate does not change either hosted browser site: the root app
continues to follow `main`, and `/preview/` follows `develop`. The bundled manual
matches the candidate; hosted app/manual links can show an earlier revision.

The source includes `RELEASE-CANDIDATE.md` with the qualification record and
remaining runtime checklist. Experimental capabilities and open platform checks
remain limits of this prerelease until additional evidence is recorded.
