# Numerical provenance and migration notes

Reference: `CPrescher/MossA`, commit `d201482b7990afbd0e2dcc23e306bfc8d60a5049` (MATLAB code retained under `reference/MossA`; the license file was updated to MIT at the author’s request). The browser and native Rust code share one numerical implementation.

## Preserved conventions

| MATLAB source | Port behavior |
| --- | --- |
| `lorentz_curve.m` | Area-normalized Lorentzian, `hwhm = fwhm / 2` |
| `gauss_curve.m` | Literal rounded constants `0.8326` and `1.7725`, rather than silently replacing them with exact constants |
| `pseudov_curve.m` | `mix × Lorentzian + (1 − mix) × Gaussian` |
| `lorentz_squared.m` | Original squared-Lorentzian expression, including its width convention |
| `doublet*.m` | Centers `CS ± QS/2`; A12 is the first-line area fraction, not an arbitrary ratio |
| `sextet*.m` | Original `0.1613`, `0.0934`, and `0.0255` field coefficients, QS shifts, and A12/A13 ratios; line areas sum to the intensity parameter |
| `cta_fit.m` | Thin-absorber spectrum is physical polynomial background minus summed absorption profiles |
| `cta_fit.m` / `cft_fit.m` result tables | Site intensity fraction is `100 × I_i / sum(I)`; raw intensity parameters remain separately visible |
| `cft_fit.m` | Source convolution with `exp(−sum(absorber profiles))`; fixed grid `−30:0.01:30`; MATLAB `conv(...,'same')` alignment; intensity scaling by `I0/100`; shape-preserving cubic interpolation to experimental velocities |
| `fold.m` | The original 1-based integer/half-integer circular pairing and summed counts |
| `MossA.m` velocity calibration | Linear or sinusoidal velocity axis, then subtract standard center shift |
| `MossA.m` mouse definition | Position/depth, then width, then opposite-line position for doublets/sextets; profile-specific height-to-area estimates and original `3.097` sextet starting-field conversion |

The full-transmission convolution is computed with zero-padded FFTs instead of a direct convolution. The result is checked against independently summed convolutions. Its finite-window and grid effects are retained, rather than renormalizing the source or replacing the reference model with an infinite-window approximation. Default analytical evaluation uses a real-to-complex FFT and complex-to-real inverse of the same 16,384-point padded signal, retaining 8,193 Fourier coefficients. Source and absorber derivatives use that same transform and normalization. The explicit numerical override retains the original full complex FFT. The two algorithms differ at floating-point roundoff; [staged benchmarks](validation-data/performance/SHARED-REAL-FFT.md) check minima, std, rank and uncertainty availability independently.

Thin fitting uses bounded variable projection by default with analytical derivatives; an explicit `thin_solver: "joint"` keeps joint fitting. Only independent roots whose nonzero uses are exclusively background coefficients and/or site intensities are eliminated; cross-links into line-shape parameters retain that root in the nonlinear problem. An active-set bounded linear least-squares solve uses column-scaled pivoted QR. The reduced Jacobian includes the residual-dependent Golub–Pereyra term, with bounded numerical differences at nonsmooth active-set/distribution limits. Finalization always uses the original full Jacobian, scales, rank threshold, parameter count, degrees of freedom and uncertainty conventions. An omitted `thin_solver` selects variable projection for thin analytical fits. Numerical derivatives, bounded-LM recovery and unsupported linear systems retain joint fitting.

## Deliberate implementation choices

- **Solver:** Basin 3.2.0's bounded trust-region-reflective algorithm, using a pure Rust dense linear algebra path. This is not a reproduction of MATLAB's optimizer trajectory or `fmincon` algorithm. Tolerances, iteration counts, and final parameter values can differ.
- **Scaling and derivatives:** Independent coordinates are scaled by their starting magnitudes with sensible floors. Bound-aware finite differences use a nonzero step even when a starting parameter is zero. The reference's `calcJacobian.m` uses a relative step that becomes zero at zero; that failure is not retained.
- **Links:** Resolve proportional links as a graph before model evaluation; reject cycles/missing targets. Descendant bounds intersect with the independent source bounds, including negative factors. The optimizer never treats linked/fixed coordinates as independent variables. xVBF mixture normalization is implemented separately using bounded independent coordinates; see below.
- **Bounds:** Widths and sextet ratios have positive physical floors; intensities and field magnitudes are nonnegative. Doublet A12 and pseudo-Voigt mix are constrained to `[0,1]`. Initial values outside the combined bounds are rejected, not silently changed.
- **Background:** Stored coefficients are the actual additive background polynomial. MATLAB's internal optimizer sign conventions are not used as the new project format.
- **Residuals:** The plotted residual is always `observed − model`. The default minimized objective is unweighted SSE, matching the ordinary reference fit. Optional count weighting minimizes `sum(residual² / observed)` and requires strictly positive observations. This weighting is an additional explicit option; no count floor is silently imposed.
- **Uncertainties:** Approximate **1 std** from the local Jacobian covariance, scaled by `objective / (observations − independent parameters)`. These are not `nlparci` intervals or a full constrained/nonlinear uncertainty analysis. SVD diagnoses rank deficiency; errors are omitted for unidentifiable parameters and parameters at bounds. Linked errors propagate by the absolute link factor. No symmetric uncertainty is reported for fixed parameters.
- **Intensity fractions:** The percentage definition follows `cta_fit.m:870–903` and `cft_fit.m:879–913`. Fraction std is propagated as `sqrt(gᵀ C g)` using the full scaled-coordinate covariance, with proportional links included in the gradient. This improves on the MATLAB table's propagation of individual intensity errors without covariance terms. Fraction errors are percentage points. Nonconstant fractions have no symmetric std when their contributing directions are at active bounds or covariance is unavailable. Exact constant ratios (including a single nonzero site) have 0 std within the specified model. Zero total intensity has undefined percentages. Percentages refer to intensity parameters, not measured-window integrated dips or nonlinear transmitted components.
- **Progress:** The optimizer's accepted iteration states are published through a Rust observer. Expensive curve evaluation/serialization for progress occurs at most once per 100 ms, with a separate final result. Browser computation stays in the worker. Cancellation destroys the worker; the last displayed intermediate curve is discarded and starting parameters retained.
- **Mouse starting estimates:** Thin-absorber estimates retain MossA's height/width conversions, including rounded Gaussian conventions. Doublet/sextet centers are the midpoint of the selected outer lines in either click order. Full-transmission placement uses an optical-depth estimate `−ln(observed/background)` as an initial guess; it does not claim to invert source convolution. Switching models explicitly rescales intensity values and bounds by the current constant background as an approximate starting estimate, and records that action in Status.
- **Project files:** New downloads use the `.mossa` extension; `.mossa.json` and `.json` browser projects remain readable. The internal format is unchanged. Versioned JSON keeps data and scientific model state separate from graphics. MATLAB `.map` files store MATLAB objects, including graphics-related fields; conversion requires a separate, explicit migration step.

## Site display and picking navigation

Selecting a site renders its curve after the observed points and fitted model, using a thicker colored stroke. Thin-absorber overlays retain their physical background-minus-profile scale. Full-transmission overlays use a common display-only factor, `0.8 × (I0 − min(observed)) / max(sum(absorber profiles))`, evaluated on the plotted data coordinates. This follows MossA's display convention and does not change the transmitted model or objective. These overlays are not additive transmission components. Residuals are shown as points.

During picking, only an undragged left click advances a definition step. Left-drag rectangle zoom, right-drag pan, wheel zoom, right-click unzoom, and double-right-click reset retain their normal meaning. Esc or Cancel exits picking. The lower-right instruction popup does not intercept pointer events or occupy layout space.


## Velocity calibration (browser preview.3)

The reference is `reference/MossA/calib.m` (normalization to 100; Lorentzian sextet, QS = 0; free CS, FWHM, intensity, BHF, A12, A13; constant plus linear background). The default standard field is 33 T, as in that routine, and can be changed for the actual standard/conditions. Folding uses the existing direct `fold.m` port. The browser uses endpoint-inclusive axes, consistent with the final MATLAB calibration and the main data axis; it does not reproduce the initial `-v + 2*v/N*(1:N)` off-by-one axis in the MATLAB calibration dialog.

After fitting on the provisional axis with maximum `v0`, field `Bfit`, and center `CSfit`, the browser applies the exact scale factor `s = Bref/Bfit`: `vmax = s*v0`, `stdcs = s*CSfit`. The sample axis is `vmax*u - stdcs`, where `u` is linear from -1 to +1 or `-cos(pi*i/(N-1))` for a sinusoidal drive. For the unshifted fit preview, CS, width, field, and integrated intensity scale by `s`, while the background slope divides by `s`; the predicted normalized counts remain identical. This replaces MATLAB's ten successive fit/rescale cycles with an exact transformation. Tests verify curve invariance through the compiled WASM evaluator, as well as coefficient recovery from an independent six-line Lorentzian generator.

Two initializations are tried: an estimate from minima on opposite sides of the reference and MATLAB's nominal iron starting values. Both are least-squares fits; the lower-SSE eligible result is retained. The browser requires convergence, a finite positive fitted field, and positive intensity before enabling Apply. As in MATLAB, outer lines may lie outside the measured range. Rank/bound warnings remain visible and do not automatically reject a partial pattern; users must inspect the fit and choose an appropriate initial range. Bounds on background offset are widened to 90–110% and line ratios constrained to 0.05–20 to avoid singular ratios; width and field have positive lower bounds. Failure does not modify the sample. These checks cannot establish that an arbitrary spectrum is a valid iron standard: the user must inspect its fit/residuals and choose an appropriate reference field. A measured iron reference was subsequently checked locally, including automatic folding and a partial pattern. Its raw data are not included in the repository. An executed MATLAB comparison remains outstanding.

Calibration input/import, exact scaling, full precision, reference persistence, velocity-column preservation, and one-step Undo/Redo (including previous fit metadata) are tested. Applied raw-count calibration clears current fit results; applying only future-import settings to a velocity-column project retains its existing fit. Saved reference counts, folding/drive settings, nominal field, fitted provisional field, normalized RMS (percent of the maximum count), filename, and timestamp provide calibration provenance. Calibration coefficient uncertainties and uncertainty in the reference field are not propagated into the sample fit errors.


## Automatic folding and partial iron patterns (preview.6)

`src/folding.ts` ports `getfp.m`: 24 half-channel candidate centers from `N/2 - 5.5` through `N/2 + 6`, circular pair differences, and the sum of squared pair mismatches. Integer centers skip the two self-paired turnaround positions; half-integer centers use all available pairs. The symmetry peak is refined with the same Gaussian model and starting width 8 channels, then rounded to a half-channel. The core's absorption-sign Gaussian is fit to the inverted peak, an equivalent constant-minus-Gaussian model. If Gaussian refinement does not converge, the best discrete symmetry match is retained rather than inventing a center. Flat counts with no symmetry-search signal require a manual center.

Reference calibration can search automatically before fitting, with a manual override and a separate Find fold center action. Raw-spectrum imports also search automatically when folding and Auto center on import are enabled. Counts are retained at import; the window separately reports loaded and folded point counts. Odd-length input follows MATLAB's colon-loop convention and produces `floor(N/2)` folded points. No numeric measurement is silently treated as a header or removed to obtain an even count.

The former browser-only requirement that both outer iron lines be inside the scan has been removed. Tests include an iron spectrum with only the four inner lines visible, coefficient recovery, shifted integer/half-integer fold centers, odd lengths, exact 513/514-row parsing, and the discrete fallback. A partial pattern can have ambiguous line assignments or poorly identified nuisance parameters; the initial velocity estimate and fit inspection remain necessary. Coefficient errors are not propagated to subsequent sample fits.


## Folding diagnostics (preview.7)

The MATLAB `folding.m` view's raw data and symmetry/Gaussian plots are exposed alongside overlaid reversed-left/right halves and a point plot of their difference. Pair construction uses the exact same 1-based circular indices as `fold.m`. Integer-center self-pairs contribute to displayed folded data but are excluded from the independent pair RMS denominator. The optional percentage is 100 times the pair RMS divided by the absolute mean counts of the paired halves; it does not estimate a center uncertainty. The relative symmetry score retains `getfp.m`'s scan-dependent normalization and is not a statistical confidence level.

The unrounded Gaussian center, the half-channel center actually used by folding, and the user-selected center are kept distinct. Displayed Gaussian scores are tested against the inverse of the compiled WASM evaluator's fitted model, including the original rounded Gaussian constants. An unsuccessful Gaussian refinement shows the discrete estimate without a fitted curve. Clicking bars changes only the diagnostic selection until applying/refitting. The sample dialog's Apply folding is one history step and clears old fit results; cancellation does not commit a data change.


## Portable fit restoration (preview.8)

Save project now includes the completed fit summary (errors, fraction std, rank, dof, termination, warnings), elapsed time, selected site, and a model/data binding. Browser-local autosave and file import share the fit-summary validator. No spectrum/project data is uploaded for binding or restoration.


## Automatic source-profile calibration (preview.9)

The reference is `MossA.m`'s `src_calib_btn_click` / `src_calib_model` (lines 1955–2050). A single Lorentzian absorber has a fixed user-supplied width (MATLAB default 0.097 mm/s); source width, absorber center, optical-depth area, I0, and two quadratic background coefficients vary in unweighted least squares. As in MATLAB, the source is centered at zero, sampled on −30:0.01:30, convolved with exp(−absorber), interpolated with PCHIP at the observed velocities, and **normalized by the maximum of these interpolated values** before multiplying by I0. The grid-step constant cancels on normalization. Browser additive background b1/b2 correspond to the negatives of MATLAB's second/third calibration coefficients. This normalization is separate from ordinary full-transmission fitting, whose model remains unchanged.

A private Rust prepared-model option adds `source:fwhm` as a fitted parameter and recomputes the source FFT for each trial. Dedicated WASM entry points and worker methods keep this calibration behavior out of ordinary saved-project models. A constant count-scale normalization inside the solver improves numerical conditioning without changing the unweighted least-squares minimum. Reported objectives and the final Jacobian/covariance remain in original count units. Source std is approximate local-Jacobian 1 std conditional on exact absorber width and velocity calibration; uncertainties in these inputs are not propagated.

Intentional UI/numerical differences: source widths use the existing transmission range 0.001–5 mm/s rather than MATLAB's zero-to-infinity bound; zero is singular on the discrete grid. Known absorber width must be at least 1e-6 mm/s. Initial source width defaults to MATLAB's 0.4 mm/s; an absorption-depth seed and a seed with MATLAB's area 8 and center 0 are tried. The best converged identifiable result is shown. Nonconverged, rank-deficient, or bound-limited source widths cannot be applied. Lorentzian-squared width retains `lorentz_squared.m`'s parameter convention (the parameter is not the actual half-height FWHM of the squared curve).

The dialog runs independently and updates its graph at approximately 10 Hz. Stop/Cancel does not modify the sample. Applying stores the source settings plus reference spectrum, known width, fitted nuisance parameters, approximate std, RMS, warnings, and date in one undoable snapshot; it does not replace the sample's sites/data or switch its spectrum mode. A changed source invalidates a full-transmission sample fit; an unchanged source or a thin-absorber sample retains its fit. This reference/provenance survives browser autosave and portable project files. Imported raw reference channels use the current folding/velocity controls; supplied velocity columns are preserved.

Validation uses an independent direct-discrete-convolution transcription of the MATLAB calibration expression for both source shapes, compiled-WASM parameter recovery, non-grid velocities, count-scale/noise cases, throttled progress, failure rejection, and history/session/project round-trips. MATLAB is unavailable here: this is expression-based validation, not a comparison with outputs executed in MATLAB or a measured source-standard validation.


## Gaussian-mixture source calibration

The optional `Project.source_gaussians` stores one to three `{center, fwhm, weight}` components. Weights are positive relative integrated areas. The entire mixture is normalized to unit area and recentered to zero area-weighted centroid before computing its FFT. Centers describe a **velocity-response kernel** in the convention `S(v-u) T(u)`; asymmetric shapes must not be reflected on transfer from reference to sample. Offsets and weights in saved files retain the anchored parameterization; the UI shows centered positions and normalized area percentages. The first component's center and weight are fixed during calibration, removing the redundant translation and common scale. All widths and the other offsets/weights vary. Component labels have no physical site meaning and permutations may be equivalent.

This follows the calibration principle in [Yaroslavtsev (2023), SYNCmoss, Section 2](https://journals.iucr.org/s/issues/2023/03/00/gy5045/), rather than claiming output parity with that program. A known-width Lorentzian singlet and its optical-depth area, center, and quadratic background are fitted through the existing calibration transmission model. The chosen number of Gaussians is explicit; no automatic component-selection claim is made. Source parameters are fitted only by the dedicated calibration entry points. Ordinary thin-absorber evaluation ignores the source; ordinary full-transmission evaluation precomputes the complete source FFT and holds it fixed while fitting the sample.

Gaussian widths are bounded to 0.03–5 mm/s on the existing 0.01 mm/s grid, anchor-coordinate centers to ±5 mm/s, and relative weights to 0.001–100. Calibration tries multiple initial estimates (including mirrored asymmetric seeds). Application requires convergence, full local Jacobian rank, available source-parameter std, and source parameters away from bounds. Std is conditional on the known absorber width, velocity calibration, and source family/component count; source uncertainty is not propagated into subsequent sample fits. `sourceFwhm`/`sourceStd` in the reference metadata retain the first component's width/std for backward-compatible bookkeeping; they are not the mixture's overall FWHM. Component std and the full mixture are stored separately.

For this new source family, the FFT acts on `expm1(-total_optical_depth)` and restores the unit continuum after convolution. This avoids treating zero-padded values as zero transmission at the grid edges. The kernel is also normalized on the numerical grid. Gaussian-convolved curves use six-point local polynomial interpolation at observed velocities; the legacy source families retain PCHIP. This interpolation was checked against actual SYNCmoss output at the measured standard’s off-grid velocities. Absorber calculations remain restricted to ±30 mm/s; use a sufficient velocity margin around all absorption features. The legacy Lorentzian and Lorentzian-squared paths retain their original MATLAB expressions and sampled-maximum calibration normalization. Gaussian calibration uses that same sampled-maximum normalization; ordinary Gaussian full transmission uses unit continuum without that normalization.

Mixture projects and source references are saved using format version 2, so older applications reject them instead of silently substituting a symmetric source. Exact floating-point JSON decoding preserves fixed parameters through JS/WASM round-trips.

`tests/gaussian-source.test.tsx` checks asymmetric handedness and unit continuum against independent finer-grid direct quadrature, full source recovery, transfer to a separate saturated doublet, fixed-source fitting, three-component recovery, invalid and degenerate models, and project/autosave/history round-trips. Source-extraction recovery remains synthetic. A measured SMS standard and its supplied source have now also been compared with the actual pinned SYNCmoss engine; see `validation-data/syncmoss-sms/README.md`. Measured-singlet source-extraction validation remains outstanding.


## xVBF CS/QS distributions (preview.10)

The reference is `cxVBF.m`, `csite.m`, `cta_fit.m`, and the literal four-pole `voigt_curve.m` expression. A Lorentzian doublet can use one to eight Gaussian CS components and one to eight Gaussian QS components. Each CS/QS pair produces equal-area lines at CS ± QS/2, with Gaussian-width parameters sqrt(wCS² + wQS²/4 ± δ wCS wQS), correlation δ in [−1,1], and fixed Lorentzian parameter 0.194. Pair areas are total site intensity × CS weight × QS weight / 2. The legacy `voigt_curve.m` argument names say FWHM, but its scaling is not conventional spectral FWHM; those numerical parameters are retained and the editor labels them Width. A zero effective Gaussian width uses the analytic limit of the same approximation instead of dividing by zero.

The solver uses bounded stick-breaking coordinates for independently fitted weights. Conditional feasible intervals account for all remaining weight bounds and the mass left after fixed weights, so every evaluated trial respects the sum-to-one condition, nonnegativity, and bounds. A distribution with N freely varying weights has N−1 independent weight coordinates. The last weight is derived; fixed values remain unchanged. Approximate weight and mean-CS/QS std propagate the full local covariance through this nonlinear transformation. Active-bound directions and rank deficiency withhold affected symmetric uncertainties. The fit degrees of freedom count independent coordinates, not displayed fields. This enforces the intended MATLAB normalization even where the old thin-absorber equality-matrix indexing could omit a distribution.

Intentional full-transmission correction: `cft_fit.m` comments out distribution weight variables and multiplies every CS/QS pair by the same area. The browser uses the normalized weights in both modes; its full-transmission result therefore differs from that legacy path for multiple components. Fixed flags and bounds are honored for intensity and every distribution parameter. Direct proportional links on/to distribution weights, centers, widths, and coupling are not exposed; ordinary site-intensity links remain supported. The initial QS width is fixed while CS width and coupling can vary; a single symmetric doublet cannot independently identify both widths and correlation. Redefine on graph is disabled for an xVBF site; edit its distribution centers/widths in xVBF. Switching xVBF off restores ordinary profile editing.

All component parameters, fit flags, bounds, and the coupling participate in autosave, history, and the project/model binding. xVBF autosave uses session version 2, and portable files use project version 2 with an explicit required feature so older browser versions reject them rather than silently read an ordinary doublet. Existing version-1 browser files remain supported. The main results table shows distribution mean CS/QS; component widths do not imply one effective spectral FWHM. Parameter CSV export includes means, δ, all component centers/widths/weights and their std. Component weights and their CSV std are fractions (0–1); the editor shows weights in percent and their std in percentage points. Undo/Redo and reload restore completed fits/errors without optimization.

Validation includes independent MATLAB-expression mixtures over positive/negative/extreme coupling, a separately summed full-transmission convolution, synthetic coupled-width and mixture-weight recovery, all-trial simplex boundary tests, dependent-weight covariance and active bounds, invalid-input rejection, editor add/delete, and history/autosave/project round-trips. No measured xVBF standard or executed MATLAB fit is available; these are expression-based and synthetic validations. Magnetic hyperfine-field distributions are outside this CS/QS xVBF implementation.

## SMS input and persistent velocity reversal (preview.16)

Single-spectrum SPEC MCA input requires one `@A` count block and one consistent `#@CHANN` declaration, with 8–20,000 finite nonnegative counts. Continued rows are flattened in acquisition order. Acquisition headers are retained; `#@CALIB` is not a Mössbauer velocity scale. Multiple blocks, missing/extra counts, malformed tokens, and inconsistent declarations are rejected. The supplied five-column singlet references are recognized only after checking the total/difference against directional counts; the recorded velocity and total columns 1–2 are used without recomputation or normalization. Import format/selection and headers where available are retained with spectra or calibration references.

`reverseVelocity` follows `MossA.m`'s `flip_btn_click`: negate the complete calibrated x coordinate, including the center-shift correction. The browser reorders paired observations to keep x strictly increasing. Raw channels and calibration/reference/preset settings are retained. A spectrum-owned `velocityReversed` flag survives later raw recalibration and folding, autosave, portable files, and Undo/Redo. All model fits of an affected spectrum are invalidated; site starting parameters are not transformed. New imports start in their original direction.

Reversed single-spectrum files use version 3 with `velocity-reversal-v1`; reversed collection/autosave files use version 2. Older clients reject those versions. Existing nonreversed version 1/2 single-spectrum files and version 1 collections remain readable and retain their conventions.
